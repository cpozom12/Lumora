# CPZ Fork Baseline

This document records the initial engineering baseline for the `cpozom12/Lumora` fork.

- Initial working branch: `agent/bootstrap-media-center`

## Current technical baseline

The fork starts from the upstream application without product-identity changes so that we can first prove the original codebase builds and runs cleanly.

- Kotlin
- Android Views/XML
- Media3 / ExoPlayer
- Room + WorkManager
- OkHttp
- `minSdk = 25`
- `targetSdk = 36`
- Java/Kotlin JVM target 17
- Current application id: `com.lumora`
- Current upstream version observed: `4.2` (`versionCode = 30`)

## Phase 0 — reproduce upstream before customization

1. Keep `main` as the stable fork baseline.
2. Make changes only on isolated branches (`agent/*` initially).
3. Run the repository CI before product modifications:
   - Android lint
   - unit tests
   - `:app:assembleDebug`
4. Install the resulting debug APK on the target Android phone.
5. Validate normal phone playback and Android Auto behavior while the vehicle is stationary.
6. Record device/head-unit compatibility findings before changing package identity or playback architecture.

## Product direction

After the vanilla baseline is proven, the fork can evolve into a CPZ-owned media client focused on:

- IPTV providers already supported by upstream.
- Jellyfin/Plex/media-server workflows where supported.
- Offline media.
- Faster in-car stationary UX and large-touch-target navigation.
- Independent package identity, branding, release signing and GitHub Releases.
- Clean separation between upstream-compatible core changes and CPZ-specific product changes.
- Evaluation of commercial streaming integrations only through supported/legal platform mechanisms; no DRM or service-access bypasses.

## Android Auto boundary

Android Auto/video behavior must remain compatible with the host platform's parked-only restrictions. This fork will not implement mechanisms intended to defeat motion-based video restrictions.

## Planned branch model

- `main`: stable CPZ baseline/releases.
- `agent/*`: isolated implementation branches and experiments.
- Upstream changes are reviewed before merging into `main`; avoid rewriting upstream history.

## Upstream sync strategy

For local development, configure the original project as an additional remote:

```bash
git remote add upstream https://github.com/disclosurez/Lumora.git
git fetch upstream
```

Before pulling upstream changes into the CPZ product line, compare/review them first and merge through an isolated branch/PR rather than pushing directly to `main`.
